# Configuration write operation registry (v3)

Status: **design only / implementation paused**. This is the single executable definition for repairing DEV-ESCAPE-CONFIG-001. A future implementation must derive its public composition exports, runtime validation, negative tests and concurrency test participants from these rows. The count of registry rows must equal both the rows whose operation schema is tested and the independent matrix-participant count; repeated callers cannot hide behind a shared area-level test.

## Boundary and common rules

- `sync-config-store` owns the private `writeTail`, queue-fresh read, normalization, backup and temp-plus-rename. It exports no callback/mutation/replacement API to application/web composition.
- Each listed operation accepts the exact schema stated here. Unknown keys, aliases, whole configuration/sync/platform/LAN/Agent/override maps, deep copies and stale snapshots reject before any disk read or write; `user.json` bytes must remain unchanged. A “binding” is one `{agentId, providerId}` pair; a “field” is one whitelisted scalar key. No operation accepts a map of bindings or fields.
- `null` is invalid unless an operation explicitly assigns it delete meaning. Omitted fields never delete. Timestamps are strict ISO-8601 UTC; invalid timestamps reject; a timestamped operation retains the later valid value.
- Remote payload is decoded before entering the store into the listed per-section operations; it is never supplied as an arbitrary “intent”/callback/config object. Provider sites remain outside `user.json`; models cache is never in an A→B payload.
- Each `race` identifier names a distinct temporary-HOME+USERPROFILE real-disk test participant. The final test asserts `registry.operations.length === executedParticipantIds.size`.

## Registry-derived test gate

The test harness imports the registry data rather than a second hand-maintained list. For every row it must run: (a) schema unknown/alias/deep-copy/full-snapshot rejection with byte-identical disk, and (b) the row's single named race participant using real store I/O. A test fails if registry row ids, verified schema row ids, dynamically discovered adapter ids, or executed participant ids differ.

The existing dynamic adapter acceptance remains mandatory: runtime `AGENTS_META` and `getAdapters()` must equal the ten adapter rows above; an A→B encrypted payload containing no cache must hydrate models locally before native configuration files are asserted. This is a cross-check, not a replacement for individual operation rows.
